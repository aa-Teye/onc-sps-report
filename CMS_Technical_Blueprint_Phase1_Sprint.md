## Project Overview

**Goal:** Build a unified Church Management System for Generations Chapel that begins with Shepherding Placement System (SPS) reporting and attendance tracking, then layers additional modules (membership, events, giving) incrementally.

**Why this approach?**
- SPS is the most urgent need (178+ groups, currently on WhatsApp)
- Build modular so each phase plugs cleanly into the previous one
- Start simple, prove the pattern, scale incrementally
- Learning from ONC SPS (what worked) and Event Management System (reusable patterns)

**End goal:** One centralized backend serving multiple frontends:
- Shepherd SPS reporting app
- Member registration/profile portal
- Event check-in & registration
- Admin dashboard (role-based, multiple tabs)

## Technology Stack

### Backend
- **Framework:** FastAPI (Python)
- **Hosting:** Render (free tier, auto-scales to zero)
- **Database:** Neon (PostgreSQL, free tier, never pauses)
- **Authentication:** Custom JWT (FastAPI-based, zero third-party dependencies)
- **Image Storage:** Cloudinary (for member photos, event media)
- **ORM:** SQLAlchemy + Alembic (database migrations)

### Frontend
- **Framework:** React 18 + TypeScript
- **Build tool:** Vite
- **Hosting:** Vercel (free tier)
- **State management:** TanStack Query (for server state) + Zustand (client state)
- **UI Components:** shadcn/ui + Tailwind CSS
- **Forms:** React Hook Form + Zod validation
- **Charts/Analytics:** Recharts

### Infrastructure
- **Source Control:** GitHub (private repo)
- **CI/CD:** GitHub Actions
- **API Documentation:** OpenAPI/Swagger (auto-generated by FastAPI)
- **Monitoring:** Free tier (Sentry optional)

### Brand Design
- **Primary Dark Green:** `#1B5E20` (Generations Chapel logo)
- **Accent Gold:** `#D4A574` (logo border)
- **Accent Lime Green:** `#B4D84A` (success states)
- **Light Background:** `#F8F9FA`

```
├──────────────────┬──────────────────┬──────────────────────┤
│  Shepherd App    │  Admin Dashboard │  Member Portal       │
│  (SPS Reporting) │  (All modules)    │  (Registration)      │

│  - Dashboard     │  - Attendance tab │  - Event signup      │
│  - Profile       │  - Members tab    │  - Giving            │
│                  │  - Events tab     │                      │
└──────────────────┴──────────────────┴──────────────────────┘
           │                 │                    │
           └─────────────────┼────────────────────┘
                             │
                    ┌────────▼────────┐
                    │  Render FastAPI │
                    │   Backend       │
                    ├─────────────────┤
                    │  Auth (JWT)     │
                    │  API routes     │
                    │  DB operations  │
                    │  Validations    │
                    │  Cloudinary     │
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
    ┌───▼───┐          ┌──────▼──────┐      ┌────▼────┐
    │ Neon  │          │ Cloudinary  │      │ Webhook │
    │ Postgres       │ (Images)     │      │ Queue   │
    └───────┘          └─────────────┘      └─────────┘
```

**Data Flow:**
1. User submits SPS report in Shepherd App (React)
2. Frontend POSTs to `/api/reports/sps` (FastAPI)
3. Backend validates, checks duplicates (server-side), stores in Neon
4. Returns JSON response
5. Admin Dashboard subscribes to changes via polling or WebSocket
6. Display updates in real-time

## Database Schema (Neon PostgreSQL)

### Core Tables

#### `users`
```sql
id (uuid, primary key)
email (string, unique)
phone (string, optional)
password_hash (string) — bcrypt hash
role (enum: admin, overseer, zonal_pastor, branch_pastor, shepherd, member)
zone_id (foreign key → zones)
branch_id (foreign key → branches)
is_active (boolean)
created_at (timestamp)
updated_at (timestamp)
```

#### `zones`
```sql
id (uuid, primary key)
name (string)
pastor_id (foreign key → users, zonal pastor)
created_at (timestamp)
```

#### `branches`
```sql
id (uuid, primary key)
name (string)
address (string)
zone_id (foreign key → zones)
pastor_id (foreign key → users, branch pastor)
service_times (jsonb) — {day: "Sunday", time: "09:00"}
created_at (timestamp)
```

#### `sps_groups`
```sql
id (uuid, primary key)
name (string)
zone_id (foreign key → zones)
branch_id (foreign key → branches)
shepherd_id (foreign key → users)
max_size (integer, default 15)
status (enum: active, inactive, multiplied)
created_at (timestamp)
```

#### `sps_group_members`
```sql
id (uuid, primary key)
group_id (foreign key → sps_groups)
member_id (foreign key → members)
joined_at (timestamp)
status (enum: shepherd, team_member, seeker, established)
```

#### `sps_reports`
```sql
id (uuid, primary key)
group_id (foreign key → sps_groups)
shepherd_id (foreign key → users)
report_date (date)
shepherd_count (integer, default 1)
team_member_count (integer)
seeker_count (integer)
established_member_count (integer)
visitor_count (integer)
new_seekers (text array) — [names or count]
seekers_promoted (text array)
souls_won (integer)
group_health (text) — free text notes
attendance_flags (enum: healthy, warning, alert)
created_at (timestamp)
submitted_at (timestamp)
```

#### `members`
```sql
id (uuid, primary key)
first_name (string)
last_name (string)
phone (string, unique)
email (string, optional)
branch_id (foreign key → branches)
sps_group_id (foreign key → sps_groups, nullable)
membership_status (enum: member, first_timer, seeker, new_convert, established)
date_joined (date)
gender (enum: male, female, other)
age_range (enum: child, youth, adult, senior, optional)
address (string, optional)
invited_by (string, optional)
ministry_interest (string, optional)
photo_url (string, optional) — Cloudinary URL
created_at (timestamp)
```

#### `first_timers`
```sql
id (uuid, primary key)
first_name (string)
last_name (string)
phone (string)
branch_id (foreign key → branches)
sps_group_id (foreign key → sps_groups, nullable)
date_first_visit (date)
assigned_to_id (foreign key → users, first timers unit member)
follow_up_status (enum: not_contacted, contacted, integrated, became_member, lost_contact)
invited_by (string, optional)
prayer_request (text, optional)
created_at (timestamp)
```

#### `follow_ups`
```sql
id (uuid, primary key)
first_timer_id (foreign key → first_timers)
follow_up_date (date)
notes (text)
status_update (enum: not_contacted, contacted, integrated, became_member, lost_contact)
completed_by_id (foreign key → users)
created_at (timestamp)
```

#### `attendance` (Sunday service)
```sql
id (uuid, primary key)
branch_id (foreign key → branches)
service_date (date)
men_count (integer)
women_count (integer)
children_count (integer)
youth_count (integer)
first_timers_count (integer)
submitted_by_id (foreign key → users, branch pastor)
created_at (timestamp)
```

#### `events`
```sql
id (uuid, primary key)
name (string)
event_type (enum: scheduled, recurring)
start_date (date)
end_date (date, if scheduled)
description (text, optional)
created_at (timestamp)
```

#### `event_registrations`
```sql
id (uuid, primary key)
event_id (foreign key → events)
member_id (foreign key → members, nullable)
first_name (string)
phone (string)
email (string, optional)
membership_status (enum: member, visitor)
is_first_timer (boolean)
created_at (timestamp)
```

#### `event_attendance`
```sql
id (uuid, primary key)
event_id (foreign key → events)
registration_id (foreign key → event_registrations, nullable)
member_id (foreign key → members, nullable)
checked_in_at (timestamp)
is_walk_in (boolean)
checked_in_by_id (foreign key → users)
created_at (timestamp)
```

## Project Phases

**Deliverables:**
- Login system (JWT auth)
- Shepherd SPS weekly reporting form
- Role-based dashboards (Overseer, Zonal Pastor, Shepherd)

## Phase 1: Sprint Plan

**Duration:** 3-4 weeks  
**Sprint Length:** 1 week per sprint (4 sprints total)

### Sprint 1: Foundation (Days 1-5)

**Goal:** Auth system + database setup + basic project structure

**Deliverables:**
- [ ] Neon database provisioned, schema created, migrations set up
- [ ] FastAPI backend scaffolded (project structure, requirements.txt)
- [ ] JWT auth implemented (login endpoint, token generation, refresh)
- [ ] GitHub Actions CI/CD pipeline (auto-deploy on push)
- [ ] React + Vite frontend scaffolded
- [ ] Login screen UI (fully styled, Generations Chapel branding)
- [ ] User table populated with test data (1 overseer, 1 zonal, 1 branch pastor, 2 shepherds)

**Tasks:**
1. **Database Setup** (1 day)
   - Create Neon project
   - Run migrations (users, zones, branches, sps_groups, etc.)
   - Seed test data

2. **Backend Auth** (1.5 days)
   - POST `/api/auth/login` (email/phone + password)
   - POST `/api/auth/refresh` (refresh token)
   - POST `/api/auth/logout`
   - Middleware to verify JWT on protected routes
   - Password hashing (bcrypt)

3. **Frontend Auth** (1.5 days)
   - Login form (email, password, "Remember me" checkbox)
   - Local storage for JWT token
   - Redirect to dashboard on success
   - Error handling & validation

4. **CI/CD & Deployment** (1 day)
   - GitHub Actions: run tests, deploy to Render on push
   - Vercel auto-deploy frontend on push
   - Environment variables (.env for secrets)

**Testing:**
- Manual login test with 2 users (different roles)
- Token expiry & refresh test
- Protected route test (401 on no token)

---

### Sprint 2: SPS Reporting (Days 6-10)

**Goal:** Shepherd can submit weekly SPS reports, backend stores them

**Deliverables:**
- [ ] SPS report form (fully functional, all fields)
- [ ] Backend API for SPS report submission
- [ ] Server-side duplicate prevention (same group, same date)
- [ ] Shepherd dashboard (basic, shows last report)
- [ ] Role-based access (shepherds see only their group's reports)

**Tasks:**
1. **Backend SPS API** (1.5 days)
   - POST `/api/reports/sps` (submit weekly report)
   - GET `/api/reports/sps?group_id=X` (fetch group's reports)
   - Server-side duplicate check: (group_id, report_date) must be unique
   - Validation: all counts >= 0, souls_won <= expected range

2. **Frontend SPS Report Form** (1.5 days)
   - Date picker (defaults to last Sunday or last meeting date)
   - Attendance count inputs (shepherd, team, seekers, established, visitors)
   - New seekers input (text area or comma-separated names)
   - Seekers promoted to members (text area)
   - Souls won (count + optional names)
   - Group size check (warn if over max)
   - Attendance consistency flag (toggle "any members missing 2+ meetings")
   - Group health notes (optional text)
   - Submit & Draft buttons
   - Loading state, error messages, success toast

3. **Shepherd Dashboard** (1 day)
   - Display last submitted report (date, attendance, souls won)
   - "Submit New Report" button
   - Quick stats: group size, members, souls won this cycle
   - Link to member list

4. **Role-Based Access** (0.5 days)
   - Middleware: shepherds can only POST/GET their own group's reports
   - Zonal pastors see all groups in their zone
   - Overseers see all reports

**Testing:**
- Submit report, verify it's stored in Neon
- Try duplicate (same group, same date) → should fail
- Try with invalid data (negative numbers) → should fail
- Token for different shepherd → should not access other group's reports

```

Request:
{
  "email": "shepherd@generationschapel.org",
  "password": "SecurePass123",
  "remember_me": true
}

Response (200):
{
  "access_token": "eyJhbGc...",
  "refresh_token": "eyJhbGc...",
  "user": {
    "id": "uuid",
    "email": "shepherd@generationschapel.org",
    "role": "shepherd",
    "zone_id": "uuid",
    "branch_id": "uuid",
    "name": "John Doe"
  }
}

POST /api/auth/refresh
Request:
{
  "refresh_token": "eyJhbGc..."
}

Response (200):
{
  "access_token": "eyJhbGc..."
}

POST /api/auth/logout
Response (200):
{
  "message": "Logged out successfully"

```

```

Authorization: Bearer {access_token}
```

## Deployment & DevOps

### Environment Variables

**Backend (.env):**
```
DATABASE_URL=postgresql://user:pass@neon.tech/db
JWT_SECRET=your-secret-key-change-in-prod
FRONTEND_URL=https://cms.generationschapel.org
CLOUDINARY_API_KEY=xxx
CLOUDINARY_CLOUD_NAME=xxx
RENDER_DEPLOY_HOOK=xxx (for auto-deploy)
```

**Frontend (.env):**
```
VITE_API_URL=https://api.generationschapel.org
VITE_APP_NAME=Generations Chapel CMS
```

### Deployment Steps

**Phase 1 Deployment:**
1. Push code to GitHub (branch: `main`)
2. GitHub Actions runs tests, builds, deploys
3. Backend deploys to Render (`https://api.generationschapel.org`)
4. Frontend deploys to Vercel (`https://cms.generationschapel.org`)
5. Run smoke tests (login, submit report, view admin)
6. Church staff logins provisioned

**Post-Launch:**
- Daily automated backups (Neon auto-backups)
- Monitor Sentry for errors (optional, free tier)
- Weekly performance check (Render metrics)
